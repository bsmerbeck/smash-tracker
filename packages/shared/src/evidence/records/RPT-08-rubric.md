# RPT-08: The unsupported-claim rubric — what "unsupported" means, mechanically

**Decision substrate:** D-09 / RPT-08, phase 39 plan 01 (wave 1, Evidence-Grounded Prep & Debrief
Spine). D-09 fixes the ordering: this rubric and the adversarial fixture corpus land BEFORE any
report-prose, prompt or rendering code is written, with a committed oracle shown FAILING on a
deliberately wrong-number output (a claim citing a real evidence id but stating a wrong number
must be caught).

This is the TRACKED copy that survives a clean checkout (`.gitignore:26` ignores `.planning/`),
mirroring the `SCL-01-record.md` / `TRND-01-rating-model.md` precedent in this same directory.

## Definition

A factual specific in a report output is **UNSUPPORTED** when it is not recomputable from the
immutable snapshot (`EvidenceSnapshot`) the output was generated against.

**Citation existence alone is explicitly declared insufficient.** `legacyCitationRule.ts`'s frozen
`legacyCitationOnlyVerdict` is the machine-checked demonstration: it implements exactly today's
shipped citation rule (`validatePracticePlanCitations`, `apps/api/src/reports/synthesis.ts`) —
"every evidence id a claim cites is a key of the snapshot's rows" — and `rpt08Oracle.test.ts`
proves it ACCEPTS a claim that cites a real, issued evidence id while asserting a value the
snapshot's own row contradicts (rule R2, below — the named hard case). A citation existing is
necessary but never sufficient; the value itself must be recomputable.

## Owner decision D-24: commentary is qualitative only

Since 2026-09-28 a report's connective prose carries no figure and no confidence grade of its own.
Every figure a user sees comes from a checked claim, rendered beside the prose. R4 and R5 above are
the whole rule: a section whose prose carries a digit, a number word, a percentage, a W-L-like pair
or a tier word is withheld and disclosed ("commentary withheld"), never refunded (D-22) and never a
validation failure. It replaces the earlier pattern-patching (a W-L pair licence with an
opponent-perspective marker list, a per-integer licence with non-factual numeric exemptions, and a
"confiden" gate on tier words), each of which was bypassed by a phrasing outside its closed list
(code review iteration 4, R4-CR-01 / R4-CR-02). The model prompts (`apps/api/src/reports/generate.ts`
and `synthesis.ts`) state the rule up front, so most commentary is written to survive it.

**Commentary is English-only.** The prompts ask for English, in plain text, with no Markdown
emphasis. Prose in another language is withheld when it carries a letter outside ASCII (Japanese,
Cyrillic, Greek, or an accented Latin letter outside a licensed name) or a listed number or tier
word of the app's other locales (es, fr, de, pt); other non-English prose in plain ASCII letters is
not recognised as a figure.

### The D-24 allowlist

Code review iteration 5 (R5-CR-01..04) replaced the denylist with an allowlist. Code review
iteration 6 (R6-CR-01..04) found that it ran on a FOLDED copy of the prose while the card and the
`.md` export deliver the original: a roman-numeral character folded into ASCII letters, a bidi
override was deleted while the browser still applied it, and a Markdown marker inside a word became
a space while the Markdown renderer re-joined the word. Nothing is folded any more. The check reads
exactly the text that is delivered, in this order:

1. **Markdown markers.** A Markdown emphasis or code marker (`*`, `_`, `~` or the backtick)
   anywhere in the section, a tag's own span included, withholds it.
2. **Consume licensed names.** A canonical fighter or stage name that a claim in the section
   licenses, and a licensed opponent tag that contains a letter, consume their exact spans (as
   written, composed or decomposed), so the digits, symbols and accented letters inside them
   ("Pokémon Stadium 2", "Mr. Game & Watch", "Sparg0", "José") are never figures. Nothing else
   consumes anything: the same accent, digit or symbol outside a licensed span is judged like any
   other character. A digit- or numeral-bearing name or tag directly followed by a count word (see
   the lists) is a figure. A tag that itself reads as a figure or a grade ("High", "Twice", "Leo
   3-2", "Leo 3 to 2", "Leo 70%", "Leo V", or a tag holding a numeral glyph) is NOT consumed (review R5-IN-03, decided
   fail-closed), so every mention of it withholds the section: that costs commentary, never a
   claim.
3. **Allowlist.** Allowed characters: outside a licensed span, connective prose may hold only ASCII
   letters `A`–`Z` and `a`–`z`, the space, the line feed and these punctuation marks:
   `. , ; : ' " ! ? ( ) [ ] - – — ’ ‘ “ ” /`. Any other character withholds the section: a digit of
   any script, a roman-numeral character, a format, bidi or tag character, a combining mark, a
   fullwidth or mathematical letterform, a letter of another script, a tab, a carriage return, a
   no-break space, an emoji or a symbol.
4. **Word rules.** On what is left (plain ASCII by then), any casing:
   - a listed figure word or phrase, or a tier stem alone or with a listed suffix (with the
     e-final "surer", y-final "shakier"/"shakily" and "-ble" "reliably" spellings);
   - a standalone token that is a well-formed roman numeral of value two or more ("ii", "iv", "XL",
     "V", "X"), unless it is an exempt word; "I" alone is the pronoun;
   - a lone "I" or "V" beside a pair word or a hyphen or en dash ("V to I", "I-I"); "I-frame" is the
     Smash term;
   - two or more single letters joined by spaces or punctuation ("t-w-o", "H.I.G.H", "t w o"), or
     chained by apostrophes ("t'w'o"), except the listed exemptions, "I'm" and "I'd"; "a" and "I"
     standing alone are ordinary words, and a letter inside a contraction ("it's") is not single;
   - a token that, with every run of three or more of one letter collapsed to one letter or to two,
     is a listed word ("hiiigh", "twooo");
   - a token that segments into two or more listed or glue words, the first or the last of them a
     figure or tier word ("twotimes", "highconfidence", "threeandtwo"), unless it is a glue
     exemption. A word that merely contains a listed word ("often", "alone", "weight", "tone",
     "highlight", "shout") does not segment and is not read.

character or Markdown marker outside a licensed name. The prompts name them, so most commentary is
written around them.

## The verdict model

Per-claim, the validator's verdict is **`accepted`** or **`dropped`** — a claim failing any rule
above is dropped, never silently rewritten to agree with the recomputed value (an unsupported
claim is dropped and disclosed, never repaired in place).

Per-output, the verdict is **`passed`** when at least `MIN_VIABLE_CLAIMS[surface]` EVIDENCED claims survive
(abstentions are delivered but never count — owner decision D-23, one shared `countViableClaims` in the
validator and the API's pre-call fail-fast),
**`failed`** otherwise — citing the exported constant (`claims.ts`) by name so the number stays
auditable rather than duplicated in prose:

| Surface                | `MIN_VIABLE_CLAIMS` | Rationale                                                                                       |
| ---------------------- | ------------------- | ----------------------------------------------------------------------------------------------- |
| `scout`                | 3                   | Below three evidenced surviving claims a scouting output is not a report.                       |
| `prep_report`          | 3                   | Same floor as `scout` — the same claim pipeline, the same minimum bar for a shippable output.   |
| `prep_bundle_child`    | 3                   | Each bundle child is itself a full report against one opponent — the same floor applies.        |
| `post_event_synthesis` | 2                   | Rests on annotation (`vod_annotation`) claims, which are legitimately fewer per event reviewed. |

A `failed` output routes to the existing `failJob` (D-07), `failureReason: 'validation'` — the
refund path and its math are untouched.

## What this rubric cannot decide

Readability, usefulness, and tone are explicitly OUT of scope for every rule above — they are
judgement calls, not mechanically decidable facts about a snapshot, and route to the owner's
judgement at UAT rather than to a rule in this table.
