# Liquipedia fixture corpus — provenance manifest

Every byte in this directory was captured live from the permitted Liquipedia
MediaWiki API (`https://liquipedia.net/smash/api.php`) on **2026-08-11**,
under the locked access contract: a descriptive User-Agent identifying
grandfinals.gg with contact information, gzip accepted, at least 2 seconds
between general API requests and at least 30 seconds between `action=parse`
(and `action=expandtemplates`) requests. No generated HTML page was scraped —
every fixture is either a raw `action=query` revision-content response, a
rendered `action=parse` / `action=expandtemplates` response for a page whose
source content is genuinely generator-only (`{{Player vod list}}`), or the
`meta=siteinfo` response. **No further live request may be made to extend
this corpus outside an owner-approved run.**

Editor `user` and `comment` members were deleted from every committed
revision object (they are personal data this phase does not need);
`revid`, `parentid`, `timestamp`, `sha1`, `size`, and the wikitext/generated
`text` content are preserved byte-for-byte. Any asset whose sanitized plain
size exceeds 256 KB is committed gzipped (`.json.gz`, node `zlib.gzipSync`,
default level) and decompressed at load time by `loadFixture.ts`.

## Deliberately not committed

The following captured assets are NOT in this directory because they
duplicate content already present in a committed fixture, or because they
are generated-HTML pages that the locked access contract forbids scraping
from in production (their content is retained only as the `text` member of
the corresponding `action=parse` JSON envelope above):

- `sparg0-vods.html`, `hbox-vods.html`, `mkleo-lower.html`, `mkleo-upper.html` — raw HTML duplicates of the `text` member already inside `parse-sparg0-vods.json.gz` / `parse-hungrybox-vods.json.gz` / `parse-mkleo-vods.json.gz`.
- `parse-mkleo-lower.json` — the `MkLeo/VODs` twin of the committed `parse-mkleo-vods.json.gz` (`MKLeo/VODs`); byte-equivalent content (879 rows) served under a duplicate page title. Committing both would double the corpus size for zero new coverage; the duplicate-title trap itself is documented in this manifest and in `30.2-RESEARCH.md` §5.3.
